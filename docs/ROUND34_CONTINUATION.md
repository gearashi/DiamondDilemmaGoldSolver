# Round 34 continuation experiments

All full-size controls use the installed tiles and isolated databases. The reference is the validated 207-edge board in R29_INCUMBENT.json. A result on restricted domains only applies to those domains.

| ID | Evidence |
| --- | --- |
| 31 | Four domain CUDA engines on an RTX 2060 built and uploaded three immutable tables. The second engine with the same configuration reused 338,560 bytes. Different target and event layouts had distinct tables. Two nonblocking CUDA streams returned the same four independently enumerated finite Gold solutions with independent mutable state. |
| 34 | Three original side pairs passed ordinary edge and two-tile-loop checks but violated physical matching. Given all three paired prefixes, each CUDA, Vulkan and DX12 engine previously tried 41 candidates and placed 26. Each now exhausted the three prefixes with zero candidate tries. The DX12 comparison used the installed Windows SDK DXC. |
| 35 | Two simultaneous geographic requests ran their native computation once. Two defect-band workers sharing a query built one formula and ran one native solve. Forcing lease expiry prevented stale publication. An interrupted computation can still be retried. Legacy partial SAT rows storing a JSON null witness now resume. |
| 37 | On the original seed zero, a phase search ran 16 rounds then 48 more with a refit every eight rounds. The cold 64-round control agreed on board, RNG state, phases, signed and seam scores. Both scored 131. CUDA- and Vulkan-seeded runs independently matched their respective cold controls on score 122, both with 24,576 initial GPU proposals. A different cube policy started fresh. Legacy partial seeds retain their own horizon. |
| 54 | Two concurrent requests extending the same seed to 16 and 64 rounds performed exactly 64 individual rounds in both arrival orders. The native state has one renewable owner per seed and policy, while each requested horizon retains its own result. |
| 44 | A planted geographic negative transferred to narrower domains. A legal sibling stayed open and returned an independently validated single loop. A stored positive was reused only after verifying real seams, pins and their global complement, required and excluded mates, reference loss range, mandatory groups and outside count. On the original 207-board control, four narrower requests saved four native searches and four CP calls; changing physical pins ran a fresh search. |
| 45 | On the original residual at cells 6, 8, 10, 12, 14, 17, 18 and 20, the 208 test used 286 SAT decisions. A different branch width replayed its immutable clauses and counters and independently verified that loss bound. The subsequent 209 query closed before formula construction with zero decisions. Its cold control used 310 decisions and 88 conflicts. Relaxing to 207 produced a checked witness and built a wider counter. |
| 50 | Integrating phase-trajectory continuation with signed dart pricing exposed 436 repeated price builds on restart. A compressed bit matrix carries the active phase's donor prices. Resuming the 16-round checkpoint in a new problem instance matched the cold 64-round final state, including all work counters, with 451 total vector builds. The final price snapshot used 6,237 bytes of JSON for 451 vectors. |
| 51 | Two requests with different branch widths shared one concurrent structural builder and one counter builder, each returning its own valid witness. Mutating the cached clause checksum stopped subsequent reuse. |

Reproduce the individual comparisons with `python bench_r34_continuation.py device --tiles ../data/tiles.json` and the `trajectory`, `seams`, `classic` and `geographic` subcommands. The GPU controls require the full CUDA/WebGPU profile. The SQLite corruption, competing-worker and budget controls are in test_r34_query_reuse.py.
