# Incremental donor-prefix obstructions

Round 35 workstream 24 retains reuse of immutable local constraints and checked core reuse across process restarts. A prefix fixes the donor assignment on a subset of the 160 cells. Each obligation requires one of a set of seams to fail or one of the still-eligible neighboring pieces to move. The two independent caps bound movers and allowed seam failures.

The 240 published Round 34 queries used 160 cases at (3 movers, 32 failures) and 80 at (2, 31). Rebuilding all directional masks and clauses from raw piece sides agreed exactly, in order, on every query. Incremental compilation built 666 stars versus 38,400 direct evaluations. Changing the eligible pool reuses physical constraints and changes only mover masks. The held-out tests repeat this comparison on 180 permutations, allocations and pool restrictions.

Both traversals reproduced all 204 infeasible and 36 feasible results. On the first traversal the indexed basis skipped the same 116 native queries as Round 34. Time limits required 15 retries versus eight in the archived run. Reopening in reverse order skipped all 204 original infeasible-model builds. This incurred 87 first-use native verifications of independently stored cores and 36 native feasible queries, 123 native calls in total. Neither cold hash checks nor assumption labels alone establish infeasibility. A feasible forgery with a recomputed digest and a capped verifier are adverse controls.

The antichain retains incomparable mover/failure caps and incomparable mover alternatives for the same failed seams. A saved negative can cover only a more constrained clause system at equal or smaller budgets in both coordinates. The published workload contains only the two nested budgets above. Precomputing optima at other budgets adds native solves with no requests from this workload. Crossed-budget behavior is exercised in the finite controls. This bound certifies a particular donor prefix, target and eligible pool. It does not rule out a 208 board elsewhere.
