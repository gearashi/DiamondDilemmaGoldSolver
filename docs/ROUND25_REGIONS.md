# Round 25 regional reasoning work

The stages below remain opt-in. Exact finite tests establish their stated scope; they do not solve the original Gold puzzle or imply a universal runtime improvement. Development counts will be superseded by frozen-source release validation.

## 14. Reversible exact regional DAG restriction — retained

`incremental_regions` compiles selected actual puzzle regions into a complete labelled DAG. A compiled envelope is reused only when every outside domain is identical and every inside domain remains a subset of its original value. The DAG retains all cell histories, physical inventories, exposed seam masks, strand pairings and cycle counts. Narrowing or undo updates counts from changed levels toward their ancestors. Previously returned views hold immutable state and remain valid after later sibling queries. Changes outside the region or widening beyond its envelope require another compiler query.

Integration is in `RegionalResearchPruner`: at most eight selected cells with at most eight choices each use this stage, under the existing 4,096-state / 50,000-transition bounds. These are optimistic regional subproblems on the original board, not a whole-board completeness claim. Interrupted compilers continue in memory; incomplete/capped relations never narrow domains. Disk continuation is proposal 15.

The finite seven-cell, 5,040-history relation was queried in 15 narrowing/undo contexts. Cold compilation used 1,479 states and 10,206 transitions; reuse compiled 128 states and 889 transitions once, then updated 14 nodes using 98 edge checks. Including initial reverse-index construction and support-view scans, counted enumeration/edge work was 15,141 versus 6,412. The reused path additionally copied 1,792 node-count entries and performed 15 source-binding comparisons; these are reported separately and are not free. No elapsed-time claim is made.

Six focused tests cover 100 complete domain contexts against independent exhaustive Gold/edge solutions, partial regions with changed outside assumptions, overlap joins, immutable old views, 34 interruption boundaries, malformed masks, caps, semantic source changes, the actual public DFS/ResearchPruner route, and a 160-cell planted Gold witness with repeated regional reuse. Twenty-two existing regional reasoning tests also passed. Reproduce finite counts with `python -B benchmark_regions_round25.py`.

The chosen policy retains four completed envelopes and four live compiler queries. It does not promise to eliminate every repeated allocation or to preserve those caches across a process restart.

## 15. Durable unfinished regional compilation - retained

`durable_regions` implies `incremental_regions`. The compiler uses explicit frames for entry, candidate transitions and pending children, plus completed memo states, terminal signatures and exact DAG nodes. Successful cooperative Stop boundaries can save this state to the application's configured regional cache directory; fresh processes restore the exact query and continue without revisiting completed transitions. Complete relations are the only source of domain reductions. A capped cursor remains unknown, including after restart. Without a configured directory the bounded compiler still works in memory and reports that disk persistence is unavailable.

Identity includes exact puzzle geometry and strand pairings, objective, all domains, regional cells, work limits, schema and producer source hashes. JSON checksums detect damaged files; strict numeric, table, graph-level, stack and accounting checks reject malformed records. Loads that fail these checks restart the optional computation. Writes are atomic, so concurrent processes can replace a record with either complete valid cursor state; an older writer can cause repeated work but cannot remove pending branches. Entry admission is bounded to 16 local files and each file to 16 MiB; concurrent admissions may briefly exceed the entry target. Disk errors leave solving available without that save.

This is a **trusted local computation cache**, following the existing regional-table cache model. Hashes and structural checks do not independently prove that a saved table contains every legal branch. No portable frontier or external proof import accepts these cursor payloads. Independent mathematical completeness certificates are proposal 25. Unexpected errors occurring inside a compiler transition mark that in-memory cursor unusable, preventing a half-executed transition from being saved or resumed.

The seven-cell restart discriminator interrupted three processes after 200 deterministic work ticks each, then finished the relation. Rebuilding from scratch attempted 1,303 transitions; durable continuation attempted the same 889 transitions as an uninterrupted compiler, with zero repeated completed transitions and the same 5,040 histories. Four writes serialized 247,901 bytes in total, and three loads performed JSON/source/shape checks. Those overheads are additional work. This is not an elapsed-time claim; an abrupt crash can repeat work since the last successful save. In-process saves occur on cooperative interruption, completion, or after 4,096 compiler ticks.

Nine focused tests passed: all work-tick restart boundaries for both edge and Gold relations; exact agreement with the previous compiler; new-process stage continuation; completed-cache reuse; corrupt, malformed and changed-source/cap rejection; storage errors and cached unknowns; two concurrent spawned writers; unexpected mid-transition faults; actual written-byte bounds and strict pending-child/cap invariants; and the actual public DFS route with `extended_regions` disabled. Reproduce the finite record with `python -B benchmark_regions_round25.py --candidate 15 --output <report.json>`.

## 16. Compact whole-constraint seam/resource factors - retained, opt-in

`compact_factors` includes every puzzle cell, all seams and every physical piece. It builds placement patterns directly, then compiles a layered graph whose state contains unresolved seam masks and already-used pieces that still have a possible future occurrence. At a piece's last possible occurrence, the transition requires that piece to have been used and then forgets its identifier. This is valid because a complete board uses every physical piece exactly once. Labelled edges and a complete backward pass recover all supported placements without listing complete board histories.

This is a distinct representation from the older explicit pairwise factor tables; it does not materialize each pair of candidate placements first. Current ordering is deterministic cell order. Default bounds are 4,096 total placements, 4,096 graph states, 50,000 transitions, 96 exposed seams and 32 live piece resources. The full original unrestricted query usually exceeds admission limits; this stage is meant to become applicable as domains narrow. A cap returns unknown, with exact fixed-budget unknowns cached to avoid trying the same capped query again. Interrupted computations do not cache incomplete supports. Completed query supports are cached for four exact domain/limit combinations.

A 160-cell planted Gold board with three rotations for each cell's known physical piece has 480 candidates. The older pairwise construction needs 2,160 Cartesian entries and cannot finish under a 1,000-entry cap. Direct construction and complete support recovery finish in 504 candidate transitions, creating 169 states, checking 587 incoming seams and traversing 168 backward edges. Construction also prepares 480 placement patterns. The peak seam frontier is 29; the known Gold witness survives, with one edge-perfect completion. These counters represent different operations, so they do not establish universal total-work or runtime dominance.

Five focused tests passed: 80 arbitrary domain contexts match every independently enumerated edge solution and preserve all Gold solutions; resource expiration and forgetting preserve exact counts/supports; caps, cached unknowns, Stop and binding changes remain safe; a 160-cell complete query preserves its known solution; and the actual ResearchPruner/public DFS route is live. This proposal checks edge/inventory feasibility. It does not yet enforce one Gold loop; that is proposal 17.

## 17. Gold-aware whole-constraint elimination - retained, opt-in

`gold_elimination` implies `compact_factors`. Full-board states now also carry the exact pairing of every exposed strand endpoint. Closing a seam splices those paths. Any cycle closed before the final cell is impossible, because every remaining piece contains a strand; surviving intermediate states therefore have no closed cycle. A final state is accepted only after exactly one cycle closes and no exposed endpoints remain. Physical resources can still be forgotten after their last occurrence because their already-placed connectivity survives in the pairing state.

The default exposed-endpoint limit is 128, in addition to proposal 16's caps. Exceeding any cap returns unknown, never an empty proof relation. Current ordering remains deterministic cell order. Completed Gold support tables contain every supported placement. A separate labelled path recovers one complete solution; the independent puzzle validator checks it before it enters the trusted in-memory cache. DFS checks current-domain membership and independently validates that witness again, then uses its ordinary solved-result path. The witness is not forced into the domains as a deduction. Stale witnesses outside the current frame are ignored.

On the same controlled 160-cell board, exact Gold compilation accepts one solution after 504 transitions, 370 path splices, and a peak of 48 exposed endpoints. Rewiring two local strands while preserving every seam mask produces one edge-perfect arrangement with two loops. Exact Gold compilation rejects that entire full-constraint query after 213 transitions and 142 splices, finding a premature loop. This does not solve or refute the original unrestricted challenge.

Seven focused tests passed, plus the five proposal 16 regressions. Eighty arbitrary contexts agree with independent exhaustive Gold enumeration for counts, every placement support and returned witnesses. Tests distinguish early-cycle and final-multiple-cycle rejection, preserve exact cap/Stop/root semantics, exercise full 160-cell positive/negative queries, and confirm that an edge-only objective retains edge-perfect multi-loop solutions. The public Gold solver returns the recovered solution at one DFS node, with no leaf or further branch; stale and invalid witness guards are tested. Reproduce the controlled full-size comparison with `python -B benchmark_regions_round25.py --candidate 17 --output <report.json>`.

## 18. Automatic separator AND/OR search - retained, opt-in

`separator_search` constructs a graph of currently unfixed cells using both seam adjacency and shared physical pieces. It selects a bounded zero-, one- or two-cell separator, conditions all its allowed placements, and compiles the remaining components into exact interface relations. Every relation retains used pieces, exposed seam masks, strand pairing, count and one representative history. A broad invariant original outside-domain envelope makes completed component relations reusable across separator assignments; the complete join uses the actual current fixed/separator domains and includes every board cell. Gold components are never treated as independent Boolean answers.

A complete positive join yields a full arrangement checked by the independent validator. DFS can accept that Gold witness directly without requiring `gold_elimination`. Positive existence does not narrow domains using an incomplete support union. A negative deduction is published only after every admitted separator case and interface join finishes. A cap, cancellation, or absence of a useful separator remains unknown. Fixed pieces and their long paths remain in a combined exact interface, including on the full 160-cell board.

Defaults admit at most 24 unfixed cells, at most eight choices per unfixed cell, two separator cells and 64 conditional cases. Each component compiler is capped at 4,096 states; terminal-relation projection is capped at 8,192 entries. The shared work budget is 50,000 ticks, and eight complete query/component results are retained. This is an automatic bounded decomposition mechanism, not an arbitrary-width graph separator solver.

A fully enumerated eight-cell test has 72 edge-perfect arrangements and no Gold solution. Both configurations evaluate the same 37 separator candidates and four conditional cases. Reusing exact components reduces builds from four to two, compiler transitions from 84 to 42, and counted total work ticks from 609 to 487; interface joins remain four. This isolates avoided repeated component reasoning within the same planner and does not establish dominance over every other whole-board engine.

Five tests passed: 60 independently enumerated domain contexts, the component-reuse discriminator, all cap/Stop/source/cache controls, a 160-cell board whose fixed paths join two unfixed regions, and an actual one-node public DFS solution using this flag alone. Reproduce the finite comparison with `python -B benchmark_regions_round25.py --candidate 18 --output <report.json>`.


## 19. Counterexample-guided selective diagram refinement

Opt-in `selective_refinement` keeps an optimistic union diagram, checks a surviving concrete finite-factor assignment, and protects a variable implicated in a spurious assignment from future merges. Layers before that variable's assignment remain unchanged and are reused. Exact factor-support checks are cached by the factor and its projected domains. Empty complete relaxations prove a negative; exhausted work/state/refinement bounds return unknown. Finite-factor positive witnesses do not establish Gold connectivity and are never returned as Gold solutions.

The app builds complete seam/inventory factors for up to 20 cells or for an entire board with at most eight unfixed cells; otherwise it uses a selected eight-cell optimistic subquery. Fixed variables are projected exactly. Individual negative placement probes can remove candidates, and exact repeated query results are cached. Every cache key includes query domains and limits; changed source bindings are rejected. No partial reduction reaches caller domains after cooperative Stop.

Five focused tests cover 150 independently enumerated finite relation systems, 40 puzzle-domain contexts preserving every edge and Gold completion, cap/Stop/widening/malformed input cases, all 160 cells with controlled domains, and the public DFS path. On the ordinary-fixpoint tetrahedron fixture the stage removes all 12 unsupported placements (34 diagram queries, 1,947 transitions, 12,806 factor-row checks); a repeated identical query performs no diagram transitions. Its cumulative prune counter is 24 after applying the same 12 removals to two independent copies, not 24 distinct exclusions.

A late three-variable contradiction behind nine irrelevant variables requires 52 transitions when every refinement rebuilds the prefix and 34 with prefix reuse; counted work ticks decrease 116 to 89, with factor-cache lookups 128 to 74. The existing uniform-width implementation also proves this contradiction (280 of its own work ticks); these tick definitions are not interchangeable runtime measurements. This establishes a bounded reduction in repeated work, not universal performance dominance or a solution of the unrestricted Gold challenge. Evidence: `audit/optimization-round25/regions-19-finite.json` (development receipt with before/after source/runtime provenance).


## 20. Correlated symbolic inventory and connectivity interfaces

Opt-in `joint_symbolic_regions` compiles a bounded, complete two-region partition of the board. Exact terminal summaries retain placement supports. They are grouped by the complete seam masks, exposed strand pairing and cycle count, with a separate ZDD inventory family for each interface. Compatible interfaces are joined once, then exact disjoint inventory products and support queries determine which original summaries extend across the other region. Pairings and inventories are never independently pooled. Only full completed support computation can reduce domains; caps and Stop publish no partial reduction. Queries are admitted for boards of at most 12 cells or full boards with at most eight unfixed cells. This is a two-region implementation, not an arbitrary symbolic partition network.

Four focused tests cover 80 independently enumerated Gold/edge contexts, a six-cell mixed-pairing relation, caps/Stop/widening/source binding, a controlled 160-cell query, and public DFS integration. On the nine-cell ring, identical direct compilation precedes either 15,876 inventory-pair comparisons or one symbolic interface comparison with 252 inventory support probes. Total counted work decreases from 38,328 to 33,166, including 10,459 ZDD operations. The seven-cell comparison is adverse: 4,388 versus 5,467 work ticks, so this remains optional and default off. No unrestricted Gold completion or runtime dominance is claimed. Evidence: `audit/optimization-round25/regions-20-finite.json`.


## 21. Algebraic connectivity representatives

Opt-in `algebraic_connectivity` replaces explicit enumeration of all outside perfect matchings with a bounded cut-incidence basis over GF(2). A matching is incident to an anchored cut when each of its edges stays inside one side. Two incidence rows have inner product one exactly when the union of the matchings is connected: the number of shared cuts is two to the number of components minus one. A row basis therefore preserves whether any member can complete one cycle against any outside matching. Exact inventory, seam masks, cycle count and endpoint buckets remain separate. This preserves existence only, never all histories, counts or placement supports. The app applies it to its existing bounded selected regional tables; it is not a full-board connectivity solver. Maximum endpoint count is 16.

Four focused tests include 120 random matching families against every outside matching on four, six and eight endpoints, an actual eight-cell/four-strand puzzle with 30 narrowed contexts and independently checked Gold completions, Stop/caps/malformed inputs/source binding, basis reuse and public DFS. On all 105 eight-endpoint matchings, explicit connectivity-matrix construction takes 11,401 counted operations and retains eight representatives; cut incidence takes 840 cut entries plus 833 XORs but retains 35 representatives. This compression tradeoff is real. In the actual app fixture, the new route retains 11 of 12 rows with 142 basis/join work ticks, versus five retained rows and 1,176 ticks for the existing method. Shared table construction is excluded from both displayed basis comparisons; no total search or runtime dominance is claimed. Evidence: `audit/optimization-round25/regions-21-finite.json`.


## 22. Verified graph-isomorphic residual reuse

Opt-in `residual_isomorphism` builds a bounded complete residual Gold incidence graph. It contracts fixed strands into mandatory boundary paths and represents every remaining cell, physical resource, legal choice, occupied port, choice-specific segment pair and seam. Fixed inventory/seam checks and ordinary seam consistency remove impossible choices before permanently unused ports are omitted. Color refinement and bounded backtracking propose a bijection; a separate full replay checks every vertex color, edge label and adjacency before any completed support result is transported. Neither a hash nor an incomplete mapping is authority, and original piece interchangeability is never assumed. Complete Gold factor support computation supplies cache entries. Only Gold queries with one to eight initially unfixed cells and at most 768 graph vertices are admitted; unsupported self-seams and resource caps remain unknown.

Four focused tests cover 80 independently enumerated Gold support contexts, a near-miss edge-label graph, Stop/caps/fixed failures, original 160-cell geometry with controlled domains, and the public DFS route. Three non-geometric equivalent residual contexts of a controlled 160-cell ring reduce complete compilations from three to one, transitions from 497 to 165, and total counted work including graph construction/matching from 5,956 to 2,955. This ring is a test topology, not the original polyhedron. The seven-cell case regresses from 448 to 507 ticks; default-off status reflects that overhead. Evidence: `audit/optimization-round25/regions-22-finite.json`.


## 23. Gold-aware exact rational regional pricing

Opt-in `gold_pricing` extends the inventory-only regional master with exact seam/Gold interface marginal rows and nonnegative coupling columns for compatible interface pairs. It uses a complete two-region partition. Local history columns are generated by exact DAG pricing with physical-piece and terminal-interface dual weights. OR-Tools/GLOP only proposes a rationalized dual. A negative requires exact Farkas checks on all static/generated columns followed by a second exact pricing replay over every omitted history column. Fractional feasible results remain merely possible; they never produce Gold solutions. Missing GLOP, caps, nonexact duals and interrupted work remain unknown. Explicit app selection requires OR-Tools; direct callers retain conservative unknown fallback.

Five tests cover exact terminal-weighted pricing against 30 independent history enumerations, independent full-history certificate replay, 30 puzzle-domain contexts preserving all Gold completions, unavailable dependencies and malformed duals, limits/Stop/source binding, controlled original 160-cell geometry, and public DFS. On the eight-cell negative fixture the inventory-only master remains possible after three rounds/four columns; the Gold-aware master proves infeasibility in three rounds/four generated history columns, with 208 priced DAG edges including its exact certificate replay. Complete regional compilation adds 88 transitions and 34 states. This is a stronger bounded fractional relaxation, not unrestricted branch-and-price, and it does not solve the original Gold instance. Evidence: `audit/optimization-round25/regions-23-finite.json`.


## 24. Joint linkage through mandatory fixed chains

Opt-in `multichain_routing` contracts fixed strands, then asks whether one port-disjoint cycle can visit every mandatory fixed chain while sharing a single placement/orientation and physical-owner assignment across all routes. A chosen tile may supply several distinct strands to several routes; there is no unsound unit capacity per tile. Mandatory endpoints cannot be passed through without visiting their chain. The bounded search memoizes only completely failed route states. Positive linkage remains a necessary relaxation because unvisited optional strands may still form unwanted loops. Only exhaustive failure can prune; caps and Stop remain unknown. Current admission limits are 16 initially unfixed cells, eight mandatory chains, 128 route ports and 768 residual incidence vertices.

Four focused tests cover all 15 six-port matchings under four center domains, a shared-label conflict where each chain separately passes the previous two-route test, a positive case using three distinct strands from the same physical tile, limits/Stop/cache/source binding, controlled original 160-cell geometry and public DFS. In the actual four-cell star discriminator, three fixed U-chains surround a center tile whose rotations each connect two chains while isolating the third. The previous single-chain test passes; joint linkage proves failure using 12 routing steps plus 83 graph-work ticks. A center tile joining all three chains passes (three independently validated Gold rotations, six routing steps). This demonstrates stronger necessary reasoning, not whole-search runtime dominance. Evidence: `audit/optimization-round25/regions-24-finite.json`.


## 25. Independently checked complete regional certificates

Opt-in `region_certificates` produces a complete semantic-state DAG for a selected region. Every original domain choice is present, including rejected transitions and legal transitions to dead children. The producer deliberately omits its outside-domain feasibility optimization, so the artifact describes an optimistic selected-region relation. An independent verifier derives rotated segments from actual tile data, reconstructs transitions with a separate DSU/frontier implementation, checks complete edge coverage and exact child states, requires every recorded state to be reachable, and recomputes terminal counts and placement supports. Input hashes bind the puzzle, objective and exact full query; they do not authorize deductions. No accepted-history list, checksum, incomplete cursor or claimed complete flag replaces these checks.

Completed artifacts are stored separately in `regional-certificates-v1`; this is distinct from proposal15's trusted-local unfinished continuation cache. A new process verifies the entire certificate before applying support deductions. Missing, malformed or corrupted files trigger cold recomputation; cooperative Stop during verification propagates without publishing partial results. The store admits at most16 files per directory (concurrent first admissions may slightly exceed that target) and16MiB per file, using atomic replacement. Failed writes do not stop solving. Self-seam certificates are outside the supported scope. Memory reuse holds only successfully checked results.

Six focused tests cover 60 independently enumerated full Gold/edge contexts and two independently enumerated partial-region relations, ten omission/dead-child/count/support/type/root corruption variants, verification cancellation, untrusted-file recovery, write failures, a complete certificate on controlled original 160-cell geometry, and public DFS integration. Producing it performs889 compiler transitions plus889 additional export-reconstruction transitions, followed by889 independent verification transitions. The separate export counter prevents treating compiler transitions as the entire producer cost. Later import avoids compilation and export reconstruction but still performs889 proof transitions.
