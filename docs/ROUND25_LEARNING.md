## 1. Persistent SAT core lifting - retained, opt-in

The standalone session now optionally creates separate guards for restricted cell domains. An UNSAT core suggests a larger domain box; a separate native verifier reconstructs the root formula, installs only independently validated Gold-loop clauses, and checks the suggestion using excluded-placement assumptions. Search selectors and the suggested core are not proof authority. Only a completed independent UNSAT answer permits exact subtraction from queued cubes and optional scoped coverage recording.

Unknown or interrupted verification preserves every unverified sibling. The original just-completed cube remains closed. A capped subtraction preserves the prior cover; a separately completed proof can still enter the scoped ledger. Disabling the option retains the previous single-selector path. The optional policy is retained in backward-compatible checkpoints; old snapshots default to disabled. Caller-owned input lists are copied to immutable cube tuples. No additional checkpoint schema is needed because the exact remaining frontier remains authoritative.

Access: `sat_core_lifting` with persistent SAT (normalization enables `persistent_sat`). Counters distinguish primary queries, verification queries, verifier model builds and verifier decisions; count both native search and verification when assessing work. Result `nodes` and `session_total_decisions` include both, while `session_decisions` and `session_core_decisions` retain the separate breakdown. Attempted calls and consumed decisions survive interruption and checkpoint restart.

Finite discriminator: twelve disjoint contradictory four-cell cubes require 12 primary SAT queries without lifting, versus 1 primary query plus 1 independent verification with lifting, ending with the same empty frontier. This demonstrates avoided repeated proof queries, not a universal speedup or an original Gold solution. Forty seeded queue contexts across the edge and Gold objectives agree with complete independent board enumeration. Additional tests reject forged overbroad suggestions, retain work after unknown verification, preserve siblings on Stop, check coverage scopes, and exercise unchanged old session behavior.

Development command: `python -B -m unittest -v test_constraint_learning_round25.CoreLiftingTests test_constraint_sat_session` (18 tests passed; process exit zero, including interrupted primary-call accounting and verifier counters across checkpoint restarts). Reproducible logical-work command: `python -B benchmark_learning_round25.py --candidate 1 --output <report.json>`. ## 3. Resumable proof checker - retained, opt-in

`resumable_proof_checking` enables proof transport and retains trusted live verification cursors. A cursor owns immutable CNF/proof bytes, checked clauses, and the current partial unit-propagation assignment and scan position. Each bounded tick commits at most one clause visit or proof-line transition. Cancellation is polled before advancing, so no completed visit is repeated. Only a fully checked empty-clause proof admits a mask exclusion. Caps, incomplete slices, malformed bytes and changed root/objective bindings cannot create exclusions.

The mask-conflict importer now keeps partial verifications across work leases. Its previous three-try eviction remains unchanged when disabled. The constructor flag is forwarded in standalone DFS, worker/coordinator paths and app runtime/disk import stores. At most eight exact certificate cursors are retained, with the existing 4096-step, 524288-byte and 2,000,000-total-clause-visit bounds. On a total cap the optional certificate is dropped while its ordinary claim remains eligible for existing independent SAT verification. Cursors are not serialized: process restart rechecks imported bytes from the beginning.

Finite discriminator: a non-unit contradictory theory with four clauses over two variables has a valid RUP trace preceded by 80 redundant independently valid clauses. Equal small work leases let the new cursor complete while repeated fresh verification cannot finish; the report counts all clause visits in both policies. A reversed implication chain confirms that partial propagation within one proof clause resumes with exactly the old complete checker's clause visits and propagations. 120 seeded three-variable CNFs agree with exhaustive truth tables and the prior checker. A real puzzle mask certificate spanning multiple importer leases is admitted without a native SAT call and never prunes before completion.

Development command: `python -B -m unittest -v test_constraint_learning_round25.ResumableProofTests test_constraint_proof` (13 tests passed, exit zero). Reproducible command: `python -B benchmark_learning_round25.py --candidate 3 --output <report.json>`. Work counters include `mask_proof_clause_visits` and `mask_proof_resumptions`.

## 5. Verified native SAT clause subsets across restarts - retained, opt-in on tested platforms

`native_sat_persistence` implies `persistent_sat` and saves a bounded subset of independently verified native clauses. The producer is strictly gated to Glucose4 in python-sat 1.9.dev15, CPython 3.12, Linux x86-64 or macOS x86-64/ARM64. It is off by default. Windows proof logging remains disabled: the tested Windows wheel's proof variants either failed cleanup, lacked proof support or were unavailable. The earlier child-process capability results remain evidence for that specific limitation; successful Linux and Mac runs establish the supported exception.

This feature does not serialize the native decision stack, activity scores or complete learned database. Every saved derivation is independently checked again against the exact reconstructed edge/inventory CNF, variable map, initial domains, puzzle fingerprint and objective before any clause is applied. Original CNF auxiliary variables are allowed under that exact identity; solver-created selectors and unknown IDs are excluded. Native assumptions and Gold-derived clauses never become checker axioms. Validated Gold-loop cuts are reconstructed separately in the main solver. A failed saved derivation permanently rejects that checker. A checkpoint never activates logging by itself: Windows can independently verify and import a saved safe subset with the option off, using an ordinary nonlogging solver.

Reads are limited to 16 KiB, unverified pending claims to 64 KiB, retained derivations to 1024 steps/256 KiB, applied clauses to 256, and the native-clause snapshot to 512 KiB. A 4 MiB monitored native-file threshold retires the logger and rebuilds ordinary SAT while preserving unfinished cubes, independently validated Gold cuts and checked clauses. Polling can overshoot this threshold; it is not an OS-enforced file-size ceiling, and peak bytes are reported. Stop retains only a bounded unverified tail, which cannot prune until rechecked after resume. Telemetry reports logging/import/off/continuing-without-logger status and the disabling reason. RUP visits and propagations remain separate from native SAT decisions.

Completed fresh-process discriminators, identical in all three supported-platform runs:

| Finite case | Baseline decisions / conflicts | Placement-only import | Original-CNF import | Independent verification visits per restart |
| --- | --- | --- | --- | --- |
| Eight-piece/seven-slot pairwise inventory encoding | 8957 / 7406 | 4473 / 3768 | 4473 / 3768 | 732969 |
| Same inventory contradiction with sequential auxiliary encoding | 1724 / 1416 | 1950 / 1606 | 1509 / 1261 | 3966599 |
| Four-cell puzzle, complete enumeration of 72 arrangements | 495 / 94 | 495 / 94 | 596 / 103 | 2045 |

Both inventory encodings complete the same UNSAT proof after restart. All 72 independently enumerated puzzle arrangements remain available. Auxiliary imports have a useful inventory discriminator but worsen the small puzzle's enumeration. Verification also makes these short runs slower overall; fewer native decisions do not imply less total work. The feature therefore remains experimental and optional, with no original-puzzle performance claim. Measured producer log peaks were 22905, 46097 and 208 bytes respectively; the sequential case reached the retained-step cap safely.

Final focused validation passed **24 tests on each of Linux x86-64, Intel Mac and Apple Silicon**, including actual proof logging and cleanup, interrupted native prefixes, a public-session timeout boundary after a real native call, fresh restore, finite solution preservation, malformed/scoped imports, Stop, unknowns, limits and unavailable-platform rejection. ## 6. Symbolic completed and unfinished coverage - retained, opt-in

`symbolic_coverage` is available with `dfs`, `parallel-dfs`, and `sat`; SAT use also requires `persistent_sat`. It is unavailable with `hybrid` or the GPU engines. Selecting it enables `shared_coverage` and computes exact union/difference using reduced multi-valued decision DAGs. Disjoint mask-labelled edges merge equal children and skip unrestricted axes. Completed-region authority remains the existing checksum-checked, scope-bound SQLite records. Verified records are streamed with cancellation checks, so the DAG node cap can stop construction without eagerly materializing the ledger. The cache is invalidated by external SQLite commits, unrecognized local connection changes, a changed target root, or a changed node cap. Known local completed records extend the existing union atomically; a twelve-record growing-ledger regression confirms one build followed by twelve exact extensions. Pending cubes become a symbolic union before exact subtraction, then are exported as disjoint cubes for existing native/CPU/SAT runners.

The app's parallel coordinator and persistent SAT paths select this implementation through `CoverageLedger`; live SAT option changes are respected. Node/cache and flat-export caps preserve the original pending cover unchanged. Cancellation propagates without publishing partial results. Public frontier checkpoints remain flat cube lists; this stage does not claim a new unlimited symbolic native-frontier format.

Finite discriminator: eight repeated queries over a 160-cell binary root with 255 completed eight-cell prefixes. Baseline flat subtraction counts 176800 checks; the DAG performs 509 recursive apply steps including its initial construction, retains 757 nodes, builds once and reuses seven times. Both yield exactly the same single pending box with 2**152 assignments. These are different logical operation counters, not equal CPU costs. Correctness includes 160 randomized small exact-set comparisons, cardinalities, disjoint exports, real public SAT runner routing, target/root scopes, external updates, corruption, caps and Stop. The 13 focused/new+legacy tests pass with process exit zero. Reproducible command: `python -B benchmark_learning_round25.py --candidate 6 --output <report.json>`.

## 7. Mixed-theory proof DAGs - retained, opt-in

`mixed_proof_dag` enables resumable proof checking, proof transport and smart learning. The existing mask-conflict store can produce and import a bounded graph of verified deductions. Each node proves that a particular conjunction of cell domains is impossible under the bound puzzle, initial domains and objective. Hall shortages, independently validated proper Gold loops, exact GF(2) contradictions and integer pseudo-Boolean derivations supply checked leaf clauses. RUP nodes combine those clauses with the reconstructed edge/inventory CNF; a weakening node can apply a completed result to narrower domains. Hashes identify content, while semantic checking establishes validity.

Completed nodes can be reused across certificates in the same live context. A fresh process independently checks imported nodes again before admitting the root exclusion. Incomplete RUP work can resume through the proof cursors from proposal 3, but an unfinished root, a missing dependency or a resource cap never authorizes pruning. The app routes this through `VerifiedMaskConflictStore`, including existing DFS, parallel and hybrid callers. A regression produces and transports a Gold-only contradiction without invoking native SAT; ordinary independent verification remains available when bounded proof generation does not finish.

The graph retains at most 256 completed nodes and eight live RUP cursors; an exported bundle is limited to 512 KiB. A generated RUP combination uses at most 128 retained parent clauses and 512 bounded-DPLL decisions, with the existing proof-line and verification-work limits. Automatic affine-leaf discovery currently considers puzzles of at most 16 cells, and automatic PB-leaf discovery at most eight; these are bounded discovery mechanisms, not arbitrary theory-proof generation. Imported arithmetic is checked with exact integer types and explicit size limits. Gold bindings include actual strand pairings and seam-port wiring, not only endpoint masks. Evicted dependencies require rebuilding rather than an incomplete exported proof.

The recorded development discriminator constructs two refutations of a two-cell Gold puzzle. Independent complete enumeration finds 18 edge-perfect arrangements and no Gold solution. Checking the two certificates in separate cold contexts checks 41 nodes; sharing completed nodes checks 21 and reuses 20. The measured certificates combine Hall, proper-loop and RUP nodes. Affine and PB leaves have separate semantic and tampering regressions; their inclusion is not evidence of additional gain in this discriminator. Counts measure checked proof nodes, excluding proof construction and other checking costs, and establish no original-puzzle search-node or timing improvement.

Development validation recorded 30 focused mixed-proof, ordinary-proof, cursor and PB checks after independent review corrected strict integer validation and strand binding. Tests cover altered roots/objectives/content, invalid parents, partial verification, cancellation, native-free store transport, and floating-point cancellation that must not refute a valid Gold board. The saved report is `audit/optimization-round25/learning-07-finite.json`; it is development evidence, separate from final frozen-source validation. Reproduce the finite comparison with `python -B benchmark_learning_round25.py --candidate 7 --output <report.json>`.

## 8. Complete higher-order projected relations - retained, opt-in

`higher_order_relations` enables the existing SAT assistant and adds `ProjectedRelations` to actual DFS propagation, including parallel worker runtimes. A fresh selector guards temporary tuple blockers. Every native call includes all effective job/current domain masks, including when the helper belongs to the broader shared worker model. Each returned model is independently checked for masks, piece uniqueness, seam equality and verified Gold cuts. It also seeds the existing witness pool. Only a final UNSAT query commits a complete allowed relation; partial or capped model lists never prune.

Complete relations retain three-cell projections by default (the bounded API also supports four). Defaults allow 256 models, 16 native calls per lease, eight pending sessions and 32 completed tables. Clauses are reserved against a shared native-helper lifetime cap of 32768, counting initial guards, blockers and retirement units; job eviction does not refund that allowance. Mutation is marked poisoned before blocker insertion and tuple retention, so an exception between them forces guard retirement and rebuilding. Completed tables survive cancellation before later filtering. Scope widening disables inapplicable relations, and original puzzle/root/objective bindings are checked on every query. Cursors/tables are not trusted from disk.

Two configurations were evaluated. Recompiling every covered narrower context spent 275 projection queries by 80 contexts, caused table churn and was rejected. The retained policy reuses an existing covering relation and leaves additional effects of outside-domain changes to the ordinary assistant. A narrowing confined to projected cells is represented exactly by restricting its complete table; narrowing elsewhere keeps it as a sound overapproximation.

The retained finite comparison starts from a real four-cell puzzle fixture and reaches ordinary seam/Hall/pruner fixpoints before each query. Both sides enable witness pooling and support-cover batches. Among 200 seeded candidate contexts, 135 survive that fixpoint. Baseline uses 51 native queries and 178 decisions. The candidate uses 16 compilation queries plus 12 subsequent ordinary-assistant queries, 28 total, and 162 total native decisions; both build the same SAT model once. The 15 projected tuples exactly match independently enumerated complete edge arrangements, and both pipelines preserve the same completions and supported selected-cell values. This is evidence of avoided repeated proofs in that scope, not an original Gold solution or a universal runtime gain.

Development validation: 37 tests passed with exit zero (`HigherRelationTests`, existing SAT-domain tests and DFS tests), covering public DFS routing, shared helper isolation, unknowns, poisoned blocker insertion, final-proof cancellation, caps/raising caps, lifetime selector budget, scope widening and Gold-solution preservation. ## 9. Incremental affine equation bases - retained, opt-in

`incremental_affine` enables the existing `affine_reasoning` stage in the actual DFS research-pruner route. Each cell contributes exact GF(2) equations for the affine hull of its allowed endpoint patterns, with matching seam ports represented by shared coordinates. Every legal board satisfies these equations. Inconsistency can reject a context or candidate; consistency remains a necessary relaxation and does not prove that a board exists.

The extension retains four live domain/basis snapshots. For a new context, it selects a cached box that contains every current cell domain, copies that basis, and inserts equations only for changed cells. Equations valid before narrowing remain valid afterward, so unchanged-cell work need not repeat. An exact cached state can be restored on backtracking. Siblings or widening reuse a basis only when a genuine covering ancestor is available; otherwise the stage rebuilds from all cells. Completed ancestor snapshots remain unchanged during extension. Puzzle-input binding and domain checks prevent reuse after model changes or outside the original domains.

Candidate checks still use the existing exact insertion test and bounded cursor, with up to 128 candidates per call by default. A candidate's progress commits only after its complete check. Stop during extension leaves the ancestor and caller's domains unchanged; completed checks may remain available for a later lease. These are live derived snapshots, not a new serialized basis or imported proof format. The stage remains disabled when the mesh does not supply a global seam coordinate for every supported port.

The recorded development comparison isolates basis construction on 13 consistent nested contexts of a four-cell puzzle with four independently enumerated edge completions. The baseline rebuilds 13 times; the incremental policy performs one full build and 12 extensions. Equation insertions fall from 1222 to 376, and Gaussian row-work steps from 3282 to 1168, with 36 unchanged-cell reuses. Candidate testing is deliberately disabled in this measurement: both policies preserve the same context consistency, and neither reports a candidate deletion there. These counters exclude input-binding checks and dictionary copies and do not establish a timing ratio or fewer search decisions.

Separate validation covers full candidate filtering across 180 narrowed, widened, repeated and backtracked contexts, comparing with fresh bases and preserving independently enumerated completions. Six new tests plus four existing algebra tests passed during development, including interrupted extension, cache eviction, model/domain validation and the public DFS option hook; independent review found no blocker. Every retained cut has a compact dependency derivation replayed by the independent strict-integer checker; it applies only to descendants of the complete original local scope. Warm repeated filtering uses retained cuts without repeating their derivation.

The four-cell SAT-domain discriminator already survives ordinary propagation to fixpoint. Expanding the previous static PB selector to the same twelve-values-per-cell range still removes nothing. The new stage removes cell 2 codes 2 and 11, changing its mask from 4061 to 2009 and preserving all independently enumerated edge and Gold completions. The complete integrated pass tries 33 candidates: 65,960 combinations and about 1.08 million scored coefficient terms. This is **additional reasoning for two fewer candidate choices**, not less total arithmetic or a wall-clock improvement. Two learned inequalities contain coefficients up to three, rather than just rediscovered pair exclusions.

Configurations: cancellation-only parent-slack scheduling finds no cut; a 512-combination/32-derived-row budget finds none; 2,048/64 finds both; 8,192/128 finds the same two with more work. Keep 2,048/64. Configuration comparisons explicitly select the twelve unsupported values using independent enumeration; the integrated report separately includes all actual candidates and unsuccessful attempts. These finite cases do not predict original-puzzle solve time.

Safety bounds: at most five selected cells with at most twelve values each, 64 trials per call, 2,048 combinations/64 new rows per trial, coefficients and row widths bounded to 256, 16 retained scoped records with at most 64 useful cuts and 8,192 proof terms each. A stopped, capped or unsuccessful derivation proves nothing. Scope changes and mutated source binding cannot inherit a cut. The implementation is conflict-guided bounded cutting-plane discovery, not full arbitrary PB conflict analysis.

## Proposal 11 — exact integer seam and inventory lattice

Retain default-off `integer_lattice`, independently of incremental affine reasoning. Signed seam-port equations and piece-inventory equations include every cell. Choosing an origin placement per cell expresses any valid board's residual as an integer combination of within-cell difference vectors. A completed nonmembership proof excludes the context. To test a fixed candidate, its cell's entire difference family is removed and the residual is adjusted to that candidate; only nonmembership can remove it. Membership is a necessary relaxation and does not prove a complete board exists.

The four-cell discriminator removes three choices beyond ordinary propagation, GF(2) and static-PB fixpoints while preserving all six edge and four Gold completions. A planted 160-cell near-complete Gold fixture also preserves its independently validated witness, with all cells and inventory equations present. This is not a solution of the original puzzle. Independent validation includes 4000 exact `Fraction` coordinate membership comparisons, complete-solution contexts, cancellation, caps, scope changes and actual research-pruner/DFS routing.

The puzzle benefit must be stated narrowly: in 3000 seeded follow-up contexts, 2129 survived the old fixpoint and all 965 candidate exclusions were also consequences of rational-span inconsistency. No divisibility-only puzzle gain was demonstrated. A separate determinant-three arithmetic fixture distinguishes integer membership from rational and GF(2) membership; that algebra result does not establish an additional puzzle exclusion.

Defaults cap 4096 placements, 512 active equations, 250000 integer operations, 128-bit coefficients, 32 candidate trials per call and four retained contexts. A resource cap or interrupted basis leaves the relevant choice unexcluded. Fixed caps can be remembered as optional-work limits, never as infeasibility. On this discriminator, placing #11 before #10 removes two subsequent PB trials and 70064 scored terms while adding 2793 integer operations. These are separate operation counts and do not establish universal dominance or a wall-clock gain. Reproduce the finite report with `python -B benchmark_learning_round25.py --candidate 11 --output <report.json>`.

## Proposal 12 — reuse matching components after rematching

Retain opt-in `hall_rematch` (implies `incremental_hall`) after independent review found no blocker. Existing matching repair already retains valid matching edges. The extension also reuses unaffected residual SCCs when a deleted matched edge forces a new matching. Under domain narrowing, every new perfect-matching edge was supported in the old graph; the implementation explicitly verifies that its former owner belongs to the same old SCC. Changing matching owners therefore cannot merge old SCCs. Only old components whose internal residual edges changed need another traversal. Widening or a failed component check uses a complete pass; exact saved states restore on backtracking.

Six cells in three independent two-cell components provide a finite discriminator. Removing a matched edge in one pair forces rematching: the previous implementation visits all six SCC vertices, whereas the extension visits two and reuses four. Both produce identical complete supported assignments. Matching-edge tests are unchanged: this reduces repeated SCC work, not the already-localized augmenting-path work. No search-node or original-puzzle runtime gain is claimed.

New focused checks independently enumerate all perfect matchings across 700 narrowed, widened, repeated and newly seeded small contexts, and interrupt at 29 points around repair/traversal. Partial state never commits. The actual `Pruner` hook and public DFS warm policy are tested separately; turning the option off restores previous rematch policy while preserving valid exact snapshots.
