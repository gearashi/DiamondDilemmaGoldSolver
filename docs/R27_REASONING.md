# Round 27 scoped reasoning results

The original Gold model has 160 physical tiles and 240 seams. Search accepts a Gold witness only when the independent validator finds one line component on a complete, edge-perfect placement. The original-board test began with the revalidated 207-seam incumbent. The default DFS and SAT engines remain the recommendations for full-board exact search.

Whole-board MaxSAT | Available as a bounded threshold experiment | A full placement/inventory encoding contains 76,800 placement literals, 749,040 base clauses and 8,774 additional cardinality clauses at 208. The original trial stopped at its conflict budget after 25,730 conflicts and 27.36 s. The interval remained 207–240. Finite oracle tests cover every threshold, inventory infeasibility, and six different multiloop blockers. |
| 17. Unavoidable defect costs | Keep scoped preprocessing and exact cost projection reuse | Disjoint virtual zero-cost AC contradiction cores beat unary cost shifting on 35 tetrahedral scopes. The MaxSAT entry point uses a capped bound and stops early when that bound excludes the threshold. |

The held-out run used 254 nodes and 3,511 counted operations against 301 nodes and 3,324 operations with ordinary MRV. Building the second copy and joining it are required. Completion timing and pilot counts can vary with thread scheduling. |

## Reproduce

Prepare the tile data using the normal setup. From the repository root the following commands test the finite scopes and run a bounded original-board threshold search. The incumbent JSON must contain a legal full board in its `codes` array.

```text
python -m unittest -v test_r27_reason
python r27_reason.py maxsat --data data/tiles.json --seed-board runtime/best.json --threshold 208 --target gold --seconds 120
python bench_r27_reason.py --tiles data/tiles.json --seed-board runtime/best.json --checkpoint runtime/searches/dfs-gold/checkpoint.json --seconds 90 --output fresh-reason-comparison.json
```

In production DFS, enabling `easy_remainder` tests frames with at most eight unresolved cells and 64 choices beyond the first choice per cell. Each attempt has a cap of 8,000 counted operations and 40 milliseconds. DFS continues ordinary branching when the probe reaches a cap. A six-cell ring decreased from six DFS nodes to one with 48 counted tail operations. On a planted 160-cell board with three unresolved cells, the tail probe produced an independently validated Gold witness in 1,530 operations.

The checkpoint is optional. Without tiles and an incumbent, the benchmark runs the finite comparison only. For scoped commands, `--domains scope.json` supplies one list of legal orientation codes per cell. Use `backdoor`, `dynamic`, `strong`, or `orbit` to search the supplied scope. Use `orbits` to inspect one branch decision, `cost` for a defect lower bound, or `gf2 --degree 2` and `lp --degree 2` for bounded certificate searches. Python-SAT is required for MaxSAT and the concurrency control. OR-Tools is required for the LP certificate experiment.

The same five fixture roots also ran with v1.7.0's DFS and SAT. Their native decisions and DFS nodes have different costs from the counted operations inside the prototypes. The 140 paired restricted cases use the identical simple branching engine for both sides, and independently enumerate eligible complete boards to verify every returned answer. Original checkpoint samples contain 76,800, 50,766 and 23,538 allowed placements at depths zero, 12 and 24. None of those bounded experiments proved an original Gold result.

The machine-readable report includes individual fixture results, work counters, calibration and held-out seeds, and domains for the favorable finite cases. [Benchmark results](r27_reason_results.json)
