# Round 26 CPU learning, SAT and arithmetic

This document records the bounded implementations and dispositions for the 26 declared scopes in F02-F07. The [Round 26 release results](ROUND26_RESULTS.md) include the consolidated frozen run and whole-application benchmarks. These mechanisms do not establish a Gold solution or universal speedup. Caps, interrupted native calls and incomplete proof production remain unknown.

Run the reproducible finite comparisons serially with `python benchmark_learning_round26.py --family F02 --evidence-stage frozen --output <fresh-report.json>`, substituting F03 through F07. The output directory must exist and the report must not exist. Frozen mode requires a clean readable Git commit; all top-level source/native artifacts, dependency identities and repository state must remain unchanged. Inputs are deterministic fixtures in the checked source tree. The runner fails on an incomplete required discriminator. Persistent theory and the optional isolated proof producer have separate `benchmark_theory_round26.py` and `benchmark_isolated_proof_round26.py` comparisons.

## F02: durable CPU reasoning

F02.01 preserves job-local learned clauses, utility counters, pending clause-pruning progress and first-UIP reason ancestry. Records are tied to the actual owned root, objective, decisions, policy and relevant source dependencies. Loaded counters are subtracted at helper entry so historical work is not reported twice. Bounded oversized reason graphs skip this optional cache rather than aborting the search.

F02.02 retains singleton, pair and constructive-disjunction plans, completed subqueries, partial private domains and the current propagation stage. Python seam/inventory propagation has an explicit microstep cursor. Completed strong stages survive interruption; an interrupted opaque strong stage retries that stage. The native basic propagator remains one opaque call: if interrupted after sound reductions, its arc queue is conservatively rebuilt, because its internal native instruction cursor is not available. It does not claim instruction-level native continuation. Full DFS integration handles both native and Python routes, preserving exact domain/path/option identity.

F02.03 saves indexed proof-checker progress under exact CNF, assumption, proof-byte, source and budget bindings. Restoring this trusted local cursor does not make it an external proof. External proof records always undergo the independent checker.

F02.04 uses atomic temporary-file replacement, unchanged-record suppression, selective source invalidation, bounded per-context/global eviction and stale private temporary-file cleanup. The global optional-cache limits default to 512 MiB and 4096 records. Scope/source/schema changes cold-reconstruct the affected cache; unsupported schema migration never promotes old unchecked state into authority. Concurrent writers may cause conservative cache loss and the global cap is best-effort, but neither eviction nor cache failure removes unfinished search work.

The new propagation discriminator compares 12 seeded four-cell contexts through a planned interruption, includes the prefix in both policies, and checks the complete output domains against independent solutions. Resuming preserves the uninterrupted work counts; restarting repeats ten arc checks per context. Separate every-microstep, pair/constructive, native opaque-call and application archive tests cover Stop, widening, malformed state and cold process ownership. Snapshot bytes and rebuild/index work are reported separately.

## F03: shared SAT ownership and semantic witnesses

F03.01-F03.02 use a parent-owned manager service with one to eight affinity instances. Each instance owns and serializes its native model. Batches contain at most 16 requests; native leases are bounded. Worker views preserve every job restriction. Exact completed queries are deduplicated; unknown answers are never negative cache entries. Clients poll Stop while an RPC finishes. Work completed after caller cancellation may populate the service cache, but cannot return as an answer to the stopped caller. Per-request deltas attribute SAT, construction, broker and witness work once. Direct projected-table enumeration retains a separate local native helper.

F03.03 stores semantic support boards, not native solver stacks. Loads revalidate boards from raw tile segments. Domain indexes, checked Gold-cut invalidation and bounded coverage-based retention preserve their role as witnesses for the current relaxation. They are not automatically Gold solutions. A process restart rebuilds native models and reloads validated boards; exact negative RPC results remain a warm service cache.

F03.04 permits only verified oriented cell automorphisms and physical-piece bijections whose complete rotated segment pairings match. Equal edge masks alone are insufficient. The public verifier accepts physical rotation offsets; the automatic expansion is bounded to four exact-equivalent piece transpositions per source witness, so it does not enumerate an unbounded symmetry group.

The finite service case uses two spawned worker processes and 16 identical independently impossible placement queries: 16 cold models/queries become one shared model/query and 15 broker hits. This is a repeated-query reuse discriminator, not an unrelated-query throughput claim. Independent witness-index checks enumerate 3969 domain pairs; physical-map tests include equal-mask but different-pairing rejection.

## F04: checked explanations, theory and proof reuse

F04.01-F04.02 expose a common bounded deduction chain with explicit original domains, local root masks, decisions and independently checked premises. Seam/repeated-neighbor, boundary, Hall, proper-loop, GF(2), integer-lattice and PB rules are replayed before a shared original-root mask consequence is admitted. Python arithmetic exports its actual checked derivation or a separately verified separator. Native CPU ancestry keeps conservative causes where a compact rule is unavailable. Reasons, job roots and rollback ownership are preserved by the local archive and checked receiving-side imports.

Regional F11 certificates replay every live/dead DSU transition; F12 rechecks the stated Gold obstruction. F09/F10/F13 transport regenerates a bounded complete DSU proof under the same masks. This is fresh semantic re-proving, not serialization of those algorithms' internal cursors or a promise of minimal explanations. If this replay caps out, ordinary local pruning retains its conservative full-context explanation and no portable negative claim is emitted. The common transport is limited to 2048 events and 1 MiB. Root restrictions are removed only after another complete independent replay succeeds.

F04.03 is implemented separately by the persistent CaDiCaL theory owner. Direct propagated literals carry immutable antecedent clauses; proper-loop, Hall and affine clauses are checked under their negation. Native restart rebuilds the model and rechecks semantic reasons. Four completed puzzles and 193 narrowed queries had identical decision counts for direct and clause-only propagation on CaDiCaL. In the application comparison, the full persistent-theory profile also switches from Glucose to CaDiCaL and enables reusable guards. It solved all six finite cases within the 30-second caps, including both 24-free residuals. The baseline solved five. The isolated comparison and full profile results appear in the [Round 26 release results](ROUND26_RESULTS.md). Native Glucose proof logging remains an incompatible route.

F04.04 adds an explicit-state two-watch RUP checker and verified ordered hints. Hints accelerate work but are not authority; unproductive hints fall back to full propagation. Deletion lines can safely be ignored. The checker preserves watch order and cursors through trusted-local restoration and poisons failed mutations. Exact checked prefixes are shared in a bounded process-local pool; each new consumer still builds its index. A dependency compactor independently verifies the full trace, retains the ancestors of the first empty clause, and independently verifies the reduced trace before export.

The 404-clause/three-line proof case changes 1212 full-scan clause visits to seven indexed or six hinted visits, while separately charging 810 index literals. A completed 65-line shared prefix eliminates its repeat proof checks but rebuilds 130 index literals. The compaction discriminator reduces 33 exported lines to three with two extra checking passes; this is not claimed as a one-off speed improvement. Malformed assumptions, changed proof bytes, callback exceptions and every-microstep continuation are covered.

F04.05 uses bounded GPU failure reconstruction, an independently checked structural chain, guard minimization and a durable raw-certificate cache. Native reason bitsets alone are never proofs. Receiving-side checks authorize sharing, including Gold-only consequences. Unsupported learned-chain dependencies, overflow and incomplete minimization lose optional reuse only. Detailed production/cache/work evidence belongs to F14.

## F05: SAT guards, simplification and proof production

F05.01 interns one domain selector for each exact `(cell, mask)` under the same native root. Omitting its positive assumption imposes no restriction; selectors are never rebound or disabled. A lifetime cap uses direct excluded-placement assumptions. Rebuilds reconstruct selector state from semantic cubes. On the completed 36-cube case, added guard/retirement clauses fall from 108 to 12 with 54 native calls and 36 decisions in both cases.

F05.02-F05.03 check binary equivalence substitutions, complete bounded variable elimination and subsumption. Placement variables stay protected. Each SAT model reconstructs eliminated auxiliaries in reverse and is checked against every original clause. The original CNF remains core/proof authority. Eliminated IDs can be pinned in the search representation only when original-auxiliary learned-clause persistence is absent; otherwise pins are disabled. Regional auxiliaries have reserved IDs, and policy changes rebuild the search model/guard pool while preserving exact pending cubes.

The completed seed-2605 comparisons are mixed: ring4 decisions 117 to 109 and propagations 2628 to 1246; ring5 decisions 199 to 190 and propagations 4050 to 2438. The tetrahedron is adverse in decisions, 376 to 449, although propagations fall from 9537 to 6259. The double-face case retains 12 decisions and reduces propagations 1698 to 718. Transformation replay, model checking and construction are additional distinct costs. The earlier unpinned representation was worse and its development receipt remains historical evidence.

F05.04 evaluates safe proof production separately. The installed Windows native logging path was unsafe and stays disabled. An optional isolated Linux/WSL producer requires a clean child exit and independently checks returned RUP bytes on the host. Startup, reply hangs, cancellation, deployment and unavailable dependencies have explicit bounded/unknown behavior. A native proof log or process exit alone is never authority; no native-stack portability claim is made. Platform capability and pigeonhole proof comparisons are recorded by the root-owned producer runner.

## F06: higher-order relations and checked restart

F06.01 semijoins overlapping complete allowed tables, retaining tuple correlations and literal indexes through a fixpoint. Narrower contexts reuse live tuples; widening starts from complete rows. An actual four-cell projection fixture has 117 complete tuples. Ordinary propagation plus unary table filtering leaves its domains unchanged; semijoins remove two more orientations while preserving all 15 independently enumerated edge completions. Compilation costs 121 SAT queries in the current finite case and is reported rather than hidden behind the later join gain.

F06.02 chooses cells using checked mask-core participation, absent indexed semantic supports and recorded spurious semijoin combinations. Explicit projections support three to eight cells. These scores only select future reasoning work; they never establish exclusions. Tests confirm source signals and bounded selection, but no universal search benefit is attributed to this heuristic.

F06.03 uses canonical tuple rows, literal bitsets and a hash-consed suffix DAG. Projection operators actually traverse/reuse DAG suffixes and expose that work counter. Completed ancestor tables and unchanged scopes avoid recompilation; stronger outside restrictions can still justify further native enumeration. Native blocker clauses, poisoned commits and retired guards keep the existing bounded lifecycle.

F06.04 attaches a validated full edge board to each allowed row and a separately checked RUP certificate that the root formula plus declared valid Gold cuts and blockers for every allowed row is unsatisfiable. An imported certificate reconstructs its formula and checks completeness again. If Gold theory grew during enumeration, old extra rows may remain as a safe allowed cover: the table is then an overapproximation, not an exact projection of the newest theory. This avoids rejecting valid saved work merely because an old witness violates a newer Gold cut.

F06.05 saves independently validated observed rows from unfinished enumeration and reinstalls only their guarded blockers. They cannot prune by omitted rows. Separate ordinary support queries, without the enumeration selector, may establish individual partial consequences. The complete ring4 restart case retains three observed rows: three prefix models plus 21 resumed models produce the same 24-row cover, whereas cold repetition needs 27 models. A third helper loads the complete checked table with zero native enumeration queries, while paying independent proof/witness checking. Native support deadlines can remain unknown; tests explicitly finish a bounded discriminator rather than relying on a ten-millisecond timing assertion.

The certificate/import path is pure Python and stays tested without PySAT. Native enumeration tests skip only when that optional package is unavailable. Stops, source changes, Gold-cut growth, omitted rows, forged witnesses, stale scope, poisoned insertion and empty domains are covered. Native solver stacks and the bounded completeness-proof producer's unfinished stack are not serialized; capped certificate production leaves a warm table uncertified rather than fabricating authority.

## F07: arithmetic rules, queues and contribution lattices

F07.01 implements independent exact replay for signed-row normalization, division/rounding, saturation, weakening, positive combination and bounded lifted covers. Strict integer checks reject booleans/floats and malformed coefficients. Exhaustive Boolean-row tests check every satisfying assignment. A 160-context developmental search after the existing ordinary/GF(2)/static-PB fixpoint found no additional pruning from the extra rule discovery. That discoverer remains inactive in the app; it is not advertised as a retained improvement. The consolidated runner repeated the seeded assessment and recorded its construction work in the [machine-readable measurements](round26-results.json).

F07.02 keeps the existing conflict-guided cuts and adds an indexed row/cell queue with exact compatible-context reuse. It can resume private interrupted propagation and revisit only affected rows. A developmental 74-row/24-context case reduces complete row visits from 1776 to 1064 with identical domains and no additional deletion in either policy. The queue's cell-minimum evaluations, cache hits, skips and construction remain separate. Plain PB and conflict-guided PB now export actual compact integer derivations when explanation learning is enabled; unchanged row order is preserved in the ordinary path.

F07.03 uses exact-domain contribution trees, shared subtree integer bases and leave-one-cell-out sibling bases. Widening/rollback chooses a covering saved context or reconstructs. Each changed domain recalculates its actual placement origin; rational spans are never substituted for integer spans. A developmental 24-context case preserves 24 deletions and 1065 membership queries, reducing source vectors 3780 to 1921 and integer operations 183869 to 107093, while basis builds increase 120 to 174. This mixed work profile is reported, not collapsed into a fictitious total.

F07.04 emits sparse modular or equality functionals and checks them against every actual allowed placement column. GF(2) contradictions similarly replay local equations and global XOR; PB chains replay original scoped axioms and integer derivations. Only a checked original-root mask claim enters shared SAT/PB learning. Separator production/checking, affine certificate equations/XORs and common receiving-side verification are charged. Arithmetic tests cover 1920 exact vector-membership queries, independent complete puzzle solutions, full160 controlled witnesses, sibling origins, caps, cancellation and forged imports.

## Interpretation and remaining release gates

The 26 scopes have concrete bounded implementations or explicit evaluated non-adoption decisions. This is not a claim that every algorithm can run without a resource bound or that every conceivable future variant has been ruled out. Unsupported automatic schema migration uses safe cold reconstruction; unavailable native backends remain unavailable; extra PB discovery remains inactive after its negative discriminator. Hardware settings and fresh measurements appear in the [Round 26 release results](ROUND26_RESULTS.md). Development receipts retain their original source hashes.
