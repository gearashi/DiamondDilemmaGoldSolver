# Source images across exact search runs (59)

An inventory of twenty historical archives in the primary `runtime/runs` found 193 Python, C, CUDA and WGSL files totaling 2,207,199 bytes. The 35 distinct byte strings totaled 503,403 bytes. Repeated payloads therefore accounted for 1,703,796 bytes. The historical archives use smaller source sets than the current exact runners.

The exact runners now try a copy-on-write clone of each installed source on capable macOS and Linux filesystems. Each run keeps ordinary independent files at the same paths as previous releases. The archive writer verifies the private clone against the bytes actually parsed and hashed. A changed source, symlink, shared inode, cross-volume path or unsupported filesystem takes the ordinary data-copy path. There is no shared mutable content store. Source trees, old run directories, and checkpoint formats require no conversion. The [Linux clone operation](https://man7.org/linux/man-pages/man2/ioctl_ficlonerange.2.html) and [Apple clonefile operation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/man/man2/clonefile.2) keep changes to each file private.

A fresh path on a volume without cloning uses one ordinary write. Before replacing existing evidence, the writer stages the complete replacement privately. A process killed during a new archive can leave incomplete images in that run directory. The runner publishes its source manifest only after capturing the complete image set. Tests cover interrupted replacement, retry of an incomplete new raw file, concurrent writers, changed-source fallback and prior-run tampering.

On the actual Windows NTFS volume, block cloning is unavailable. Six captures in one process (old, new, new, old, old, new) each archived the same 209 files with matching independent SHA-256 digests. Across measurements the in-progress source was approximately 2.99 MB. In the final paired run, the ordinary path took 0.25 and 0.28 seconds warm; the new path took 0.28, 0.28 and 0.29 seconds. Both wrote the same 2,992,115 payload bytes. Linux WSL on a volume without reflink also takes the fallback. The macOS test step in the cross-platform workflow sets `DIAMOND_REQUIRE_SOURCE_CLONE=1` and requires two clone operations on the same volume and changes first the installed original and then one of the archives. The other archive must retain its exact original contents, with distinct file identities. Storage reuse is conditional on a successful native clone.

Reproduce the inventory and six-source comparison from the checkout with `python bench_r34_source_images.py --history ../runtime/runs --work audit/r34`. Choose an existing work directory on the filesystem under test. Run `python -m unittest -v test_r34_source_images` for the isolation controls.
