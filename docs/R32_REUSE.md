# Reusing work across four-swap traversals

All comparisons use freely rotating pieces and target 208. The 160-tile input fingerprint starts with e96470e2. The tests keep separate counts for position sets, center-specific permutations, physical score queries and auxiliary table entries.

| Workstream | Measured scope and decision |
|---|---|
| 8. Multicenter page dependencies | A newly computed multicenter page records direct exclusions and the earlier center and support rank owning each deferred permutation. Reuse recursively requires each dependency to be committed, in scope, and below the requested threshold. On a 128-set run for each family, a later singleton-center run inherited all 26,880 seven-piece and 13,440 eight-piece donor endpoints without new geometry. Older multicenter pages lacking ownership metadata continue to serve their original union. Regression cases exercise a missing owner, an owner two links away, a previously found witness, and a stronger target. |
| 9. Incomplete root traversals | A ranked search can derive an order’s canonical connected root and look up its completed, negative subtree. It can skip a full position set when every order has been rejected or covered. Conversely, committed negative ranked supports can skip star pricing in the root cursor. After only 24 roots on cells 0–9, the records covered 10,988 of 25,074 connected seven-piece donor orders and 3,636 of 4,710 eight-piece orders. Tests check exact membership across every connected order on nine cells. Grouped full-board cursor pages remain resumable. |
| 10. Attachment catalogues | Root search stores distinct candidate geometry and its center-specific price order in compressed, checksummed SQLite records. On the second 12-root block it reused 810 seven-piece catalogue rows or 90 eight-piece rows, with zero new price evaluations. A distinct center can reuse geometry while recomputing scores. Use `--no-catalogue` for an in-memory comparison. |
| 11. Shared exterior rotations | The compiler removes constant factors, splits exactly additive edges, indexes legal rotations only and eliminates factors within each independent component. When a table would exceed its limit, it can branch on an exterior rotation. Each branch retains its own exact boundary response. The old compiler reached its cap on all four original 160-cell supports. The replacement returned exact scores for every sampled donor order on all four. Table work totaled 2,706–3,642 entries per comparison set. Every score agreed with the ordinary exact solver. This is available through `r31_routes.py --exterior` for an explicit pool. Ordinary ranked pages rarely need a final rotation solve. |
| 12. Half-join representatives | Once occupancy and canonical ownership have selected compatible partners, group identical standalone gains and donor responses on the first half’s physical-seam boundary. Evaluate the score once per group and expand all surviving members before star and rotation checking. On two seven-piece pools this cut partner price evaluations from 1,248 to 1,143 and from 87 to 28. On the eight-piece pools the comparisons were 1,971 to 1,940 and zero to zero. Use `r30_cycle_joins.py --representatives` on restricted pools. Grouping runs after the bitset join and still takes work to classify rows. |
