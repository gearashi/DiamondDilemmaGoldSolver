# Per-lane frame checkpoint transfers

The classic search writes the cursor when trying a candidate and writes first, length and shift when initializing a stack frame. An owned native trace records separate inclusive rank bounds for those two operations. An installed lane overwrites all 160 ranks. The retained packet sends exactly the four physical unsigned 16-bit fields inside their corresponding bounds, then overlays them on the previous checkpoint. Untouched ranks keep every prior byte. A CPU-assisted search or a reader without exclusive trace ownership uses the ordinary conservative ranges.

The host validates every active span and prices the data plus the uploaded descriptor before submitting any device work. Dense or consecutive columns use implicit IDs. Nearby lanes can use a shared table of repeated endpoint values and one output offset per 32 columns. Sparse patches use explicit lanes and offsets when smaller. Every lane owns its output words, including a possible trailing half-word. Blocks individually fit the granted storage limit. The C decoder in the existing optional physical-board library validates lengths, indices and rank bounds before committing a capture. NumPy also decodes the layout. The public reader selects the span path when the verified C decoder is available and its predicted two-way traffic is strictly smaller. Other captures follow the existing rectangle path.

## Original puzzle measurements

All four replayed frame fields matched direct native copies at all 60 static checkpoints. Runs used 128 lanes, 128 spaced across 2,048, 2,048 dense and 32,768 dense lanes on each of CUDA, Vulkan and D3D12. The comparisons froze each state after another 1, 8, 64, 512 or 4,096 steps and reported medians from three warm samples. The 12 first one-step captures had no frame writes and transferred no frame packet. Among the 48 captures with writes, exact intervals reduced uploaded plus downloaded frame bytes by 11.1% to 75.1%. Together the existing rectangles moved 49,944,548 bytes and the exact intervals moved 37,602,240 bytes. The common native marks were read once per comparison and are listed separately in the JSON.

At 32,768 lanes after the 4,096-step interval, 32,203 lanes were selected. Their initialization bounds covered 464,716 ranks and cursor bounds covered 496,971. CUDA's current rectangles used 4,250,488 bytes of frame data and 903,084 bytes of descriptor upload. The exact spans used 3,846,528 bytes of data and 73,904 bytes of upload. WebGPU's rectangle descriptor cost another 640 bytes. That capture took 49.80 vs 48.53 ms on CUDA, 51.30 vs 52.24 ms on Vulkan and 67.05 vs 62.20 ms on D3D12, shown in each case as current rectangle followed by compiled span. The compiled span was faster in 37 of the 48 nonempty comparisons. The NumPy decoder was faster in one. These results compare frame capture and immutable merge on one Windows GPU, with search work suspended during replay.

An independent native control split all three initialized fields from the cursor strip. A second packed all four fields in the initializer strip and only the cursor on its exterior. Each of those alternatives tried strip overheads of 0, 256 and 4,096. Every variant needed more combined bytes than the exact per-lane packet on all 48 nonempty snapshots. Some produced a smaller download but repeated enough column indices to exceed the savings. Removing all remaining word padding could recover at most 0.79% to 1.91% of current packet traffic on these controls and would save zero physical field reads. The retained format keeps independent lane words.

The regressions exercise rank 160, cursor-only writes, sparse rows, mixed high unsigned values, dense palette packing, stale tails, a lane install over an invalid old mark, impossible grants, incomplete packets, damaged endpoint pairs and a price rejection with zero device work. A maximum-width 131,072-lane full replacement splits at a 128 MiB storage grant. Device-specific tests write arbitrary physical data independently of the host history. The normal search and checkpoint archive contain the same frame values, branch ownership and continuation information.

Run `bench_r35_frame_spans.py --help` for the backend and shape controls. A library built with `build_native.py` provides the `--native` argument. The complete physical transfer counts and timings for all nine transport/decoder settings are in [R35_FRAME_SPANS.json](R35_FRAME_SPANS.json).
