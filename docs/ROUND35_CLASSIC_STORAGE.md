# Classic checkpoint storage

The installed legacy checkpoint has 131,072 lanes and 43 NumPy members. The benchmark opened it read-only, rewrote isolated copies, and verified the uncompressed SHA-256 of every member. A stored ZIP wrote 260,191,435 bytes, level-one DEFLATE wrote 42,362,829, and level six wrote 39,157,703. Measured times were 1.40, 3.35 and 13.52 seconds. These are process I/O counters on Windows. They include file-format overhead and do not measure physical SSD wear.

The production writer now uses level-one DEFLATE for signed classic checkpoints. The file remains a standalone NPZ with its original names, dtypes, shapes and Fortran-order metadata. Hashing covers the final ZIP bytes in write order. The writer flushes the temporary file, fsyncs it, writes the generation receipt, then replaces the public checkpoint. Immutable frontier files retain their original layout. Fault injection at the member write, fsync, receipt write and final rename preserved the prior generation and its receipt. The v1.14 public solver verification preserved 480 jobs and 230,400 candidates on terminal reopen, rejected a changed RNG and rejected a shortened frontier. The archive and runner regression suite passed on Python 3.12 and 3.15. The released CUDA checkout ran under Python 3.12.

Five genuine CUDA generations with 128 active lanes wrote 106,196 bytes as level-one archives. At 2,048 lanes with 128 occupied, the total was 237,441 bytes, and with all lanes occupied it was 845,631. An independently verified content-addressed SQLite prototype at four chunk sizes wrote more bytes on every active-pool control. On the installed checkpoint the three chunk sizes wrote between 87,865,872 and 174,905,776 bytes. Parking 2,035 jobs while running one lane changed the outcome. The 64-KiB SQLite variant wrote 698,520 bytes across five saves versus 1,048,865 for the compressed standalone archive. With 8,001 parked jobs and 128 lanes, the 256-KiB variant wrote 2,152,752 versus 3,759,525. A more specialized experiment stored the verified frozen bank once and recorded its suffix offset in the active archive. Including a full portable final save, this wrote 446,739 versus 1,056,665 bytes on the first matched comparison and 1,582,430 versus 3,767,325 on the second. Without parked work both paths wrote 113,996 bytes. Every reconstructed field was compared with its source. Both genuine sequences retained the whole bank over the five saves. ## Immutable bank interval writer

Keep the first full authenticated checkpoint as a portable base. The next qualifying interval links that exact archive under its SHA-256 in the same profile, then saves only active fields and the exact remaining bank suffix. The first link is verified from disk. A reused link whose file identity changes gets checked again. A changed bank, an unsupported filesystem, or an unsuitable compressed fraction uses the full format. The active head and a full stop use different receipt names so a failed same-generation repack preserves the prior valid head. A normal stop publishes a standalone NPZ and retires obsolete private links. A same-generation final repack uses the authenticated on-disk interval and requires zero new GPU lane reads.

An actual CUDA process was interrupted after publishing a 1,911-job external bank at generation 298. A new 64-lane process restored it with verified origin and stopped at generation 1,456 in a standalone archive. It retained all 2,051 job owners across the ledger's completed, active, paused and unassigned counts. A second original workload consumed 512 of 2,176 initially parked jobs across four intervals. CUDA, Vulkan and Direct3D 12 restored the active and frozen stacks, resized them to 16 lanes, advanced them and matched the control on all 38 native fields. The five-save comparison, including a full stop, wrote 140,481 versus 240,254 bytes on this changing bank. A stable 8,001-job bank wrote 1,616,309 versus 3,766,695. [Process crash](R35_PARKED_CRASH.json) · [Reassignment and cross-backend restart](R35_PARKED_PUBLIC_FINAL.json)

Writing every available bank reference regressed when 480 active lanes shared only 32 parked jobs. The final policy requires at least 16 parked jobs and four KiB of compressed bank data. It admits a small fraction only after observing enough interval saves to cover one portable repack, using a bounded horizon of three to sixteen saves. At 33 generations the 512-to-480 case now ties standalone output at 3,450,760 bytes. The 2,048-to-1,500 case saves 1,178,915 bytes and the 4,096-to-2,560 case saves 4,074,576. One to four parked jobs stay on the portable path. These costs are from a stopped snapshot at an already saved generation, which exercises the extra full repack. ## Native frame and lane transfers

The first snapshot reads the full native state. Subsequent snapshots carry forward immutable arrays and fixed prefixes, refresh CPU assistance state and read lanes that were previously active, pending, or received an installation. The ledger records every installation, including jobs already retired again before capture. A normal frame can change only between its prefix floor and greatest attained depth, including the next uninitialized cursor. Restoring or reassigning a lane can overwrite every frame. Row intervals are chosen by dynamic programming over floor and maximum-depth boundaries. A shared descriptor gathers the four frame fields in four device maps. When every lane is reassigned, the reader takes an ordinary full snapshot. [Matched transfer controls](R35_NATIVE_RANGE_TRANSFERS.json)

At the supported maximum of 131,072 lanes, after 512 search steps per lane, a fully assigned CUDA pool transferred 72,488,448 of 216,924,160 bytes. Vulkan and Direct3D 12 each transferred 139,471,872 of 427,819,008 bytes. With 512 jobs assigned at that width, CUDA transferred 338,560 bytes and each WebGPU backend transferred 655,616 bytes. The tests compared all returned fields and dtypes. The dense CUDA snapshot took 244 ms against 143 ms for the full reader in the final paired observation. Search decisions are identical. These measurements support a transfer reduction and show the host merge cost on dense jobs. The host retains a previous immutable image while the reader is active. The public standalone checkpoint still works with a full capture. [Maximum-width and adverse controls](R35_NATIVE_RANGE_TRANSFERS.json)

Tests exercised stale stack-frame bytes from a cold archive, mixed and scattered ownership, reinstall and retirement between captures, 32-bit counter carry, older Gold rewinds, fixed and dynamic frames, forced moves, CPU-owned endgames, validated synthetic single-loop Gold, acknowledgement and subsequent resumed native steps. A separate real-puzzle CUDA process was killed after generation 223 with 1,911 parked jobs. A new 64-lane process preserved all 2,051 owners, verified the source history and published a standalone signed checkpoint at generation 973. The physical tests ran on CUDA, Vulkan and Direct3D 12 on the RTX 2060. The release workflows also exercise the WebGPU controls on software Vulkan and on a hardware Metal adapter when the runner exposes one. ### Sparse native writes and reads

The original Direct3D 12 uploader exhausted native memory installing 256 dispersed jobs into 2,048 lanes. Each fragment submitted a separate queue write. The packed path submits two uploads and one compute dispatch per eligible field. Consecutive rows and columns each need just one starting offset. Repeated coordinates use the existing serial update order. One job in 128 lanes went from 810 native writes to 17. A 384-job installation in 32,768 lanes went from 311,040 writes to 23, including the selection upload for one read. Both Vulkan and Direct3D 12 independently verified all 384 native stacks. A contiguous full 128-lane installation used 11 writes with either path. [Transfer counts and all six cutoffs](R35_NATIVE_COLUMN_TRANSFERS.json)

Four serial writes is the lowest cutoff that reduces the combined count of queue writes and submissions for a scattered field. Long strided reads use a separate cutoff of 128 rows. Smaller strided reads often favored direct buffer copies in the warm controls. The raw timings include first-use shader costs. The sparse OOM fix and the four-frame transfer decision are settled for the verified native layouts. [Read timings by row and column count](R35_NATIVE_COLUMN_TRANSFERS.json)

### Remaining board-array question

A separate screen compared every omitted board cell with the native full snapshot on 40 real transitions. Across the 4,096-step static case in a 32,768-lane pool, floor and high-water restrictions could reduce 5,152,480 board entries to 870,235. A tighter occupancy calculation identified 734,169 entries. The dynamic case had 4,992,000 entries and the occupancy calculation identified 1,812,630. All actual differences were inside the predicted sets. This is still a screen. Test an actual compact board transfer, its selection uploads, host merge cost, authoritative board and used-mask verification, and cold restart before settling this remaining part of proposal 68.
